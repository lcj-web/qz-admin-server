- 当前数据库为内存版 H2（`jdbc:h2:mem:qzdb`），**重启即丢数据**，仅有种子数据兜底。
- 实体表：`qz_country` / `qz_policy` / `qz_consult` / `qz_user`，由 `ddl-auto: update` 自动建表。
- 本地环境已具备：Java 1.8.0_421、Maven 3.9.16。

## 用户诉求：迁移到 Supabase
用户希望把项目"部署"到 Supabase 项目 `rwkyvnlmhwygkyyrrfjc`。已说明核心事实：
**Supabase 无法托管 Spring Boot jar**，它只提供 Postgres + Auth + Storage + Edge Functions。
实际需拆为两件事：① 后端改连 Supabase Postgres；② jar 另找机器运行（本机/云服务器/Docker）。

## 迁移必须改的 3 处（已出方案，用户暂未确认执行）
1. `pom.xml` 增加 `org.postgresql:postgresql:42.7.4`（Boot 2.7 默认 42.3.8 过老）。
2. **关键坑**：6 处 `columnDefinition = "CLOB"` 在 Postgres 下不合法，需改 `TEXT`（H2 亦兼容 TEXT）。
   位置：`entity/Consult.java:37`、`entity/Country.java:36/40/44/48`、`entity/Policy.java:33`。
3. `application.yml` 换 Postgres 数据源：需 `sslmode=require`；Hikari `maximum-pool-size` 调至 5。

## Supabase 连接要点
- 两种连接串：Session pooler（`aws-0-<region>.pooler.supabase.com`，用户名 `postgres.<ref>`，**IPv4 可用**）
  与 Direct（`db.<ref>.supabase.co`，用户名 `postgres`，2024 后新项目**仅 IPv6**，无 IPv6 环境会连不上）。
- 建议默认用 Session pooler 规避 IPv6 问题。
